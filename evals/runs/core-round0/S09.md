# S09: transcripts

## skill_en / opus
### t1
**TCP** sets up a connection first (a handshake). It delivers data complete and in order, resends anything lost, and slows down when the network is congested. The cost is extra overhead and delay. It's used for web pages, email, file transfers and SSH.

**UDP** has no connection: it just sends separate packets. Nothing guarantees they arrive or arrive in order, and lost packets aren't resent. That makes it lighter and faster. It's used for voice and video calls, online games and DNS lookups.

**Rule of thumb:** if you need every byte in order, use TCP. If speed matters more and losing a packet now and then is fine, use UDP.

## baseline / opus
### t1
**TCP (Transmission Control Protocol)**
- Opens a connection with a handshake before any data is sent
- Delivers everything, in order, and resends anything that gets lost
- Slows down when the network is busy, which adds overhead and latency
- Used for web browsing, email, file transfers and SSH

**UDP (User Datagram Protocol)**
- Has no connection. It just sends packets ("datagrams")
- Doesn't guarantee delivery or order, and lost packets stay lost
- Has very little overhead, so it's faster and has lower latency
- Used for video and voice calls, online gaming and DNS

**In short:** TCP gives up some speed to be reliable. UDP gives up reliability to be fast.

## skill_en / haiku
### t1
**TCP** is connection-oriented and reliable. It sets up a connection first, guarantees that data arrives complete and in order (retransmitting lost packets), and controls flow and congestion. The cost is more overhead and latency. It's used for web pages, email, and file transfers.

**UDP** is connectionless and best-effort. It sends independent datagrams with no handshake and no guarantee of delivery or order, but with less overhead and lower latency. It's used for DNS, voice and video calls, streaming, and online games, where a dropped packet is better skipped than waited for.

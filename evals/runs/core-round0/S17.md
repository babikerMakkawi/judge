## baseline / haiku
### t1
Bugs, most serious first:

1. **Wrong denominator (the main bug).** The function divides by `len(orders)`, which counts every order, including unpaid ones. It should divide by `len(paid)`. For example, with two paid orders totaling 100 and one unpaid order, it returns 33.33 instead of 50.

2. **Crash on an empty list.** If `orders` is empty, `len(orders)` is 0 and the function raises `ZeroDivisionError`. The docstring promises 0 in this case. The function also returns 0 when there are orders but none are paid, but only by accident: `0 / n` is 0. Once the denominator is fixed, that case would divide by zero, so it needs an explicit check.

3. **Generators and iterators break.** If `orders` is a generator or other one-pass iterable, the list comprehension consumes it, and `len(orders)` then raises `TypeError`. Converting the input to a list first avoids this.

4. **Money summed as floats.** If `total` values are floats, the sum accumulates rounding error (for example, `0.1 + 0.2` is not exactly `0.3`). For currency, use `Decimal` or integer cents.

5. **Strict status matching.** `o['status'] == 'paid'` silently drops `'Paid'`, `'PAID'`, or `' paid'`. If the data isn't normalized, this undercounts without any error.

6. **No validation of records.** A missing `'total'` or `'status'` key raises `KeyError`, and a `None` total raises `TypeError` during the sum. Nothing says which order caused the failure.

7. **Python 2 only:** if `total` values are ints and this runs under Python 2, `/` floors the result. Ignore this on Python 3.

Corrected version (assuming numeric totals and exact `'paid'` status values):

```python
def average_order_value(orders):
    """Return the average 'total' of paid orders, or 0 if there are none."""
    orders = list(orders)
    paid = [o for o in orders if o['status'] == 'paid']
    if not paid:
        return 0
    return sum(o['total'] for o in paid) / len(paid)
```

If you need exact currency math, sum `Decimal(str(o['total']))` values instead, or sum integer cents and divide at the end.
